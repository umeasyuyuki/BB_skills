# Workflow Spec

## Goal

`tiktok-speed` は、Claude Codeの処理時間を短くするための高速制作フロー。画像生成そのものは行わず、ChatGPTブラウザ版の画像生成Projectに貼るプロンプトを完成させる。

## Non-goals

- Pillowで画像を作らない
- Driveへ画像をアップロードしない
- OpenAI Image APIを呼ばない
- 9〜12枚の長尺カルーセルにしない
- 3500字以上の長文キャプションを必須にしない
- LINEオープンチャットURLをTikTokカルーセルに入れない

## Input Modes

| 呼び出し | 動作 |
|---|---|
| `/Tiktok-speed テーマ` | テーマから高速版を生成。タイトルは最良案を自動採用し、候補も残す |
| `/Tiktok-speed --auto テーマ` | ユーザー確認なし。曖昧な箇所は最も自然な案で進める |
| テーマなし | テーマだけを1回質問する |

小文字コマンド `/tiktok-speed` でも同じ扱いにする。

## Phase 0: Category

カテゴリは `compare / ingredient / entertainment / debunk / discovery / chain_menu` から選ぶ。迷ったら以下で決める。

| カテゴリ | 判断基準 |
|---|---|
| compare | A vs B、商品・成分・方法の比較 |
| ingredient | 食品、サプリ、栄養素、成分解説 |
| entertainment | 有名人、流行、固有名詞とフィットネス科学 |
| debunk | 誤解、迷信、危険な常識の訂正 |
| discovery | 意外な発見、保存したくなる知識整理 |
| chain_menu | 特定外食チェーン or コンビニの実商品ラインナップから◯選で紹介 |

`chain_menu` は他カテゴリと被りやすい。判定基準は「特定の店名が出ていて、その店の実商品から選ぶ」かどうか。一般的な栄養素の話なら `ingredient` に振る。詳細は `chain-menu-spec.md`。

## Phase 1: Minimal Research

高速版では深掘りしすぎない。必要なのは台本に使う根拠と論点だけ。

- 一次情報・論文・公的情報を優先する
- 断定が危険な健康・医療・薬機法寄りの表現は弱める
- 古い知識や現行仕様に依存する情報は、必要に応じて公式情報を確認する
- 根拠が弱い話は「可能性」「目安」に落とす

`chain_menu` の場合は、各商品のPFCと特徴成分の確認を行う。公式公開がない場合は「目安」と明記する運用に従う（詳細は `chain-menu-spec.md`）。

## Phase 2: Title Ideas

タイトル案は5〜6本で十分。20本評価は行わない。

必ず含める型:

- 損失回避
- 数値
- 疑問形
- 常識破壊
- 今日から使える実践

`chain_menu` の場合は数値型に「◯選」を入れると保存性が上がる。

最良案を1つ自動採用する。採用理由は1〜2行でよい。

## Phase 3: Script

カテゴリにより構成を切り替える。

### 標準構成（compare / ingredient / entertainment / debunk / discovery）

6〜7枚で作る。各スライドは画像化しやすい短文にする。

| 枚数 | 役割 |
|---:|---|
| 1 | 結論 |
| 2 | 結論を説明する要素1 |
| 3 | 2の補完 |
| 4 | 結論を説明する要素2（あれば） |
| 5 | 4の補完（あれば） |
| 6 | まとめ・今日からできるアクション |
| 7 | コメント誘導 |

6枚構成の場合は、4または5を省略する。省略しても「結論→理由→補完→行動→コメント誘導」の流れは崩さない。

### chain_menu 構成

`references/chain-menu-spec.md` を参照する。商品数は3〜5選、枚数は6〜7枚。各商品スライドにPFCと成分の効きを含める。

| 選数 | 枚数 | 構成 |
|---:|---:|---|
| 3選 | 6枚 | 結論→商品①②③→まとめ→誘導 |
| 4選 | 7枚 | 結論→商品①②③④→まとめ→誘導 |
| 5選 | 7枚 | 結論→商品①〜⑤→誘導（まとめ削除） |

## Phase 4: Image Prompt

ChatGPT画像生成Projectに貼るプロンプトを1本作る。プロンプト内に全スライド分の指示をすべて入れる。

固定:

- 1:1
- 上部にメインコピー
- 中部に補足コピー
- 下部に添付キャラクター
- 全スライドでレイアウト統一
- 日本語テキストは変更禁止

`chain_menu` の場合、中部は2行（PFC＋成分1行）構成を許容する。詳細は `chain-menu-spec.md`。それ以外の仕様は `image-prompt-spec.md` に従う。

## Phase 5: Summary Table

Notion用まとめ表は現行運用と同じくMarkdown表で出す。これは画像生成プロンプトとは別物。

表は1枚の投稿内で意思決定しやすい形にする。

- compare: 比較表
- ingredient: 効果 / 根拠 / 使いどころ / 注意点
- entertainment: 事実 / 科学的解釈 / 学び
- debunk: 誤解 / 実際 / 今日からの判断
- discovery: 発見 / なぜ重要か / 使い方
- chain_menu: 商品 / 用途 / P / F / C / kcal / 成分の効き

`chain_menu` の場合は表の直後に「※PFCは目安。公式公開なしのため、栄養成分は実測ベース」を必ず入れる（公式公開ありのときは省略可）。

## Phase 6: Caption

キャプションは短縮版。目安は900〜1600字。

構成:

1. 冒頭フック
2. 投稿の結論
3. 根拠や補足
4. 今日からの行動
5. コメント誘導

`chain_menu` のキャプションは、各商品ごとに2〜4文の段落でPFCと成分の効きをまとめる。箇条書きは使わず段落で書く。末尾に目安注記を必ず入れる。

TikTokカルーセルにはLINEオープンチャットURLを入れない。

## Phase 7: Notion Save

Notion保存が使える環境では、`notion-publishing.md` のpackage構造で保存する。保存できない場合は、最終出力をMarkdownとして返し、保存未実行を明記する。
