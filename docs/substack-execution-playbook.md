# Substack 即実行運用プレイブック

## 1. 運用の結論

筋太郎の Substack は「長文置き場」ではなく、フィットネス、栄養、サプリ、健康情報について、読者と会話しながら整理する場所として運用する。

狙うポジションは以下。

> Substack日本語圏における、話しかけやすいフィットネス・ヘルスケア発信者。

Substackでは、TikTokやXの熱量をそのまま持ち込まない。押しつけず、体験談から入り、読者には「今日から使える判断基準」を渡す。

## 2. 投稿頻度の決定

初月から以下で固定する。

| 種別 | 頻度 | 公開曜日/時間 | 目的 |
|---|---:|---|---|
| Notes | 1日5本 | 毎日 8:30 / 12:30 / 17:30 / 21:00 / 23:00 | 会話、反応検証、商品名/疑問の回収 |
| 保存版記事 | 週1本 | 金 21:00 | 信頼資産、無料購読、メールリスト形成 |
| memo | 隔週1本 | 水 21:00 | 調査過程、D1観察、開発ログの共有 |
| フィットネス関連コメント | 週3件 | 火・木・土 | 読者や近い発信者との接点作り |
| Restack | 週1本 | 土または日 | Substack内ネットワーキング |
| 週次レビュー | 週1回 | 日 20:00 | KPI、質問、次週テーマ整理 |

初月KPIは、既存戦略に合わせて以下にする。

| 指標 | 初月目標 |
|---|---:|
| 無料購読者 | 50人 |
| 保存版記事 | 4本 |
| Notes | 150本 |
| memo | 2本 |
| コメント/質問 | 合計20件 |
| フィットネス関連コメント | 12件 |
| フィットネス関連Restack | 4件 |

既存資料では Notes 週2本が基準だったが、Substackでは会話量を作るために1日5本まで増やす。5本のうち3本はAI主導、2本は侑来の指示主導にする。保存版記事は週1本を超えない。品質と専門確認の負荷を守る。

## 5. Notes の型

Notesは1投稿1テーマ。100から300字を基本にし、ミニ解説だけ500字まで許容する。

### 5.1 発見型

```text
1行目: 最近気になった違和感

本文: なぜ気になったか、何を見ると判断しやすいか

最後: 次に見てほしい商品/成分を聞く
```

例:

```text
プロテインの「独自ブレンド」、便利そうに見えるけど少し注意して見たい表示です。

何がどれだけ入っているかが見えにくいと、良い悪い以前に、自分に合うか判断しにくくなります。

次に成分表をめくってほしい商品、ありますか？
```

### 5.2 問い型

```text
1行目: 読者が答えたくなる問い

本文: 僕の仮説を短く出す

最後: 経験や商品名を募集する
```

例:

```text
サプリを選ぶとき、最初に見ているのは価格ですか？成分量ですか？

僕は最近、「安いか」より先に「1回あたり何がどれだけ入っているか」を見る方が、失敗しにくい気がしています！

みなさんはどこを最初に見ていますか？
```

### 5.3 ミニ解説型

```text
1行目: 小さな結論

本文: 判断基準を1つだけ説明

最後: 深掘り記事への布石
```

例:

```text
クレアチンは「いつ飲むか」より、まず「何g入っているか」を見た方が判断しやすいです。

タイミングの話はよく出ますが、そもそも量が少なければ期待する使い方とはズレることがあります。

今週はこのあたりを、成分表ベースで整理してみます。
```

### 5.4 フィットネス体験談型

```text
1行目: 最近の体験や迷い

本文: そこで気づいたこと、まだ迷っていること

最後: 読者の経験を聞く問い
```

例:

```text
筋トレ前のサプリ、昔は「飲んだ方が気合い入りそう！」くらいの感覚で見てました🔥

でも最近は、飲む前に「今日は本当に必要？」「カフェイン取りすぎてない？」「睡眠に響かない？」を一回考えるようにしています！

みなさんは筋トレ前に何か飲んでますか？💪
```

### 5.5 記事再投稿型

```text
1行目: 記事の一番使える判断基準

本文: 記事で扱った論点を1つだけ切り出す

最後: 記事リンク/コメント募集
```

## 6. memo の型

memoは完成版ではなく、調べている過程を出す。隔週水曜に出す。

```markdown
# タイトル

## 今日気になったこと

## 調べてわかったこと

## 自分たちの解釈

## まだ判断しきれないこと

## 実際にどう使うか

## 読者への問い
```

memoは原則 `send_email=False` のWeb公開向きに扱う。メール配信するのは、読者価値が高く保存版に近い回だけにする。

## 7. 保存版記事の型

保存版記事は毎週金曜21:00。1,500から3,000字。毎回「今日から使える判断基準」を入れる。

```markdown
# タイトル

## 先に結論
読者が今日使える判断を最初に置く。

## なぜこのテーマが大事か
SNSで誤解されやすい理由、損しやすい構造を説明する。

## よくある誤解
読者が見たことのある言説を扱う。

## 根拠・仕組み
論文、成分表、法律、安全性の観点を分ける。

## 実践するならどう考えるか
買う、飲む、避ける、相談する、待つなどの判断軸に落とす。

## 例外・注意点
個人差、疾患、薬との飲み合わせ、競技者、妊娠中など。

## まとめ
判断基準を3つに圧縮する。

## コメント/購読CTA
次に成分表をめくってほしい商品を聞く。
```

## 8. タイトル方針

煽りではなく、判断基準を示すタイトルにする。

### 使う型

| 型 | 例 |
|---|---|
| 問題整理型 | 「独自ブレンド」は何を隠しているのか |
| 判断基準型 | クレアチンはいつ飲むべきかより、何g入っているかを見たい |
| 初心者向け型 | プロテイン選びで最初に見るのは味ではない |
| 神話整理型 | 筋トレ後30分以内プロテイン説を整理する |
| 開発ログ型 | 成分表をAIに読ませると便利なこと、危ないこと |

### 避ける型

- 知らないと損
- まだ飲んでるの？
- 最強サプリ
- 絶対見るべき
- これだけで変わる

## 9. CTA定型文

### 記事末尾

```text
次に成分表をめくってほしい商品や、気になっている成分があればコメントで教えてください。

こういう判断基準を毎週整理していくので、続きが気になる方は無料購読してもらえるとうれしいです。
```

### 商品募集回

```text
今後の「成分表めくり通信」で扱う商品を募集します。

プロテイン、EAA、クレアチン、ダイエット系サプリなど、表示を見ても判断しにくいものがあればコメントで送ってください。
```

### AI発信者向け

```text
AIで下調べを速くすること自体はかなり便利です。

ただ、ヘルスケア領域では「どこを人間が確認するか」まで含めて設計しないと危ないと感じています。
```

## 10. 表現レギュレーション

### 禁止寄り

| 表現 | 理由 |
|---|---|
| 痩せる | 健康効果の断定に近い |
| 筋肉がつく | 効果断定になりやすい |
| 治る、改善する | 医療的主張に見える |
| 必ず効く | 個人差を無視している |
| 飲めば変わる | サプリ単体効果の過大表現 |
| 科学的に証明された | 雑に使うと強すぎる |
| 知らないと損 | 恐怖訴求になる |
| 最強、絶対 | 信頼文脈に合わない |

### 使う

| 表現 | 意味 |
|---|---|
| 役立つ可能性がある | 効果を弱める |
| サポートする | 主役ではなく補助として扱う |
| 判断材料になる | BBの思想と合う |
| 優先度を考えやすくなる | 読者の意思決定を助ける |
| 人によって合う/合わないがある | 個人差を明示する |
| この条件では有望に見える | 条件つきで評価する |

## 11. 自動公開の品質ゲート

人間確認を自動化する条件は、確認を省くことではなく、品質ゲートを通過したものだけを公開対象にすること。

### 11.1 ゲート項目

| ゲート | 合格条件 |
|---|---|
| 役割 | Note/memo/記事の役割が混ざっていない |
| 事実性 | 事実、仮説、意見が分かれている |
| 表現 | 禁止寄り表現を使っていない |
| 健康主張 | 効果断定、医療的主張、過大表現がない |
| 人間味 | 調べた理由、迷った点、僕の視点がある |
| 実用性 | 読者が見る場所/避ける場所/判断軸を持ち帰れる |
| 会話性 | コメントしたくなる問いがある |
| 導線 | 無料購読、コメント、Restackのいずれかに自然につながる |
| AI文脈 | AI活用の話では、人間が確認する場所が明示されている |
| 重複 | 過去30日と同じテーマ/同じオチではない |

### 11.2 自動公開スコア

| 種別 | 自動投稿ライン |
|---|---:|
| AI Note | 85点以上 |
| 指示Note | 侑来の明示指示あり + 85点以上 |
| memo | 88点以上 |
| 保存版記事 | 90点以上 |
| メール配信あり記事 | 92点以上 |

ただし以下を含む場合は、自動投稿しない。薬剤師または京大院生確認を必須にする。

- 疾患名
- 医薬品
- 妊娠/授乳
- 未成年
- 競技規則/ドーピング
- 「改善」「治療」に近い健康主張
- 特定商品の強い購入推奨

### 11.3 自動化移行条件

初期2週間は公開前に人間確認を残す。以下を満たしたら自動公開へ移行する。

- Notes 8本以上で修正率20%未満
- 保存版記事2本以上で大幅修正なし
- 禁止表現/健康主張の重大修正が0件
- 読者コメントで誤解を招く反応が出ていない

移行後も、保存版記事のメール配信あり投稿だけは週次レビューで誤配信がなかったか確認する。

## 12. MCPとskillの実行フロー

### 12.1 Notes

```text
1. Obsidianの運用方針を参照
2. substack-fit-writer の Note モードで3案生成
3. 品質ゲートで1案を選定
4. 改行を空行区切りに整形
5. post_note(text=...)
6. note_id, url, posted_at, topic を公開ログへ記録
```

Notesでは単独改行を避ける。段落は必ず空行で区切る。

### 12.2 保存版記事

```text
1. テーマを週次カレンダーから取得
2. 必要なら論文/成分/安全性を確認
3. substack-fit-writer の 記事 モードで本文生成
4. 品質ゲートと専門確認
5. create_draft(title, content_markdown, subtitle, audience="everyone")
6. 必要なら upload_image(image_path) -> set_cover_image(post_id, image_url)
7. publish_draft(post_id, send_email=True, share_automatically=False)
8. 公開ログへ post_id, public_url, title, topic を記録
9. 土曜に記事再投稿Noteを出す
```

保存版記事は、基本的にメール配信ありで扱う。ただしmemo寄り、開発ログ寄り、未確定情報が多い記事は `send_email=False` にする。

### 12.3 memo

```text
1. 調査途中テーマを選ぶ
2. substack-fit-writer の memo モードで生成
3. 「まだ判断しきれないこと」を必ず残す
4. create_draft
5. 原則 publish_draft(send_email=False)
6. コメントで追加情報を募集
```

### 12.4 予約投稿

`schedule_draft(post_id, iso_datetime)` は使えるが、MCP実装上はメール配信フラグを直接渡せない。メール配信の有無を厳密に制御したい保存版記事は、公開時刻に `publish_draft(post_id, send_email=True/False)` を実行する自動化ジョブで扱う。

## 15. フィットネス関連コメント運用

週3件、フィットネス、栄養、サプリ、健康情報に近いSubstackへ具体コメントする。

コメントの型:

```text
この記事の「{相手記事の具体論点}」という整理、かなり共感しました！

僕もフィットネス/サプリ領域で、買う前に一回止まって「これは今の自分に必要か？」を見るようにしています！

特に初心者ほど、広告文句より目的、成分量、続けやすさを見るのが大事だなと感じています💪
```

Restackの型:

```text
この話、サプリ選びや食事管理にもかなりつながると思いました！

良さそうな情報を見るとテンションが上がるけど、最後は「自分に必要か？」で考えるのが大事ですね💪
```

## 16. 週次レビュー

毎週日曜20:00に以下を確認する。

| 項目 | 見ること |
|---|---|
| 出した投稿 | Notes、memo、記事、Restack |
| Substack無料購読者 | 前週比 |
| コメント/質問 | 商品名、疑問、違和感 |
| 反応が良いテーマ | 次のTikTok/X/記事へ戻す |
| 商品候補 | BB Checker候補DBへ入れる |
| 専門確認負荷 | 楽、宍戸の確認時間 |
| 自動公開可否 | 品質ゲート違反の有無 |

## 17. 初期の自動化判断

初月は以下の運用にする。

| 種別 | 初期運用 |
|---|---|
| AI Note | 1日3本まで。品質ゲート85点以上なら自動投稿 |
| 指示Note | 1日2本まで。侑来の明示指示あり + 品質ゲート85点以上で投稿 |
| memo | 88点以上なら自動投稿。ただし健康主張が強い場合は確認 |
| 保存版記事 | 2週間は確認あり。その後90点以上で自動公開 |
| メール配信あり記事 | 92点以上。疾患/医薬品/妊娠/未成年/競技規則が出たら確認 |
| delete_draft | 常に人間確認 |

公開・メール配信も自動化してよいが、削除だけは自動化しない。
