# Note 記事生成ルール

Phase 2 の `note-writer` エージェントが従うルール。

## 関西弁トーン（★必読）

Note 記事は **関西弁ハイブリッド型** で書く。詳細ルール・OK/NG 表現・サンプルは [kansai-tone.md](./kansai-tone.md) を参照。

### ハイブリッドの使い分け

| 部分 | 文体 | 理由 |
|---|---|---|
| **地の文（説明・本論）** | 標準語 | 長文の読みやすさ |
| **論文引用・数値解説** | 標準語 | 信頼性 |
| **主張・ツッコミ・体験談・呼びかけ・まとめ** | 関西弁レベル 2 | 親しみと熱量 |
| **L2-L4 固定文（誘導末尾）** | 標準語のまま固定 | コミュニティの公式キャッチ |
| **L1 テーマ連動フック** | 関西弁 | 動的な訴求 |

段落の中で標準語と関西弁を行きつ戻りつする。「ここは事実」「ここは俺らの主張」を体感させる構成。

## 共通ガイド（先に読む）

文体の基本ルール（AI っぽさ排除、禁止ワード、語尾のリズム、定番比喩の禁止）は `../../contents-fullmake/references/writing-style.md` に従う。本ファイルは Note 固有のルールのみ記載する。

## Note の特性（Threads / X との違い）

- 検索流入を狙う媒体（SEO 意識、見出しに検索ワードを入れる）
- 1 記事で完結する深掘りコンテンツ
- 読者は「腰を据えて読む」モード、長文耐性あり
- スクロールしながら読む → 2-3 行ごとの段落区切りが必須
- 脚注・引用がエンゲージメントを上げる（信頼性訴求）
- 将来的に有料化予定（500 フォロワー後）→ 今は無料、本文の質は有料前提で書く

## 文字数

**2500〜3500 字**を厳守する。

- 短すぎ（< 2000 字）は深掘り感が出ない
- 長すぎ（> 4000 字）は離脱率が上がる
- 目安: スマホで 8〜12 分で読める長さ

## note.com コピペ最適化（A 案、★必須）

Notion ページに保存された Note 本文を、ブラウザの Notion → note.com にコピペした際、見出し・段落・箇条書き・太字がそのまま反映される形で出力する。これは Phase 4 の Notion 保存時の **block 構造** と writer の **markdown 出力規約** の両方で実現する。

### 1. 段落分割の徹底（同一ブロック内 `\n` 禁止）

writer は markdown を以下のルールで出力する。

- **各論理段落は 1 行で完結**。文中改行（行頭インデントや「、」での折り返し）を `\n` で表現しない。読みやすさのための改行は **空行（段落区切り）で表現**。
- 改行を入れたい箇所は、必ず空行を挟んで別段落にする。
- 結果: paragraph ブロックの `rich_text` は 1 行テキスト。Notion → note.com ペースト時、note.com 側で段落崩れが起きない。

NG 例（paragraph 内 `\n` で改行）:
```
ここで一番重要なんは、アルコール摂取量「1.5g/kg」という条件や。
体重 70kg の男性なら 105g。これは純アルコール量で言うと、
ビール中瓶（500ml）で 5〜6 本、焼酎なら 350ml、日本酒なら 5 合相当。
```

OK 例（1 段落 = 1 行）:
```
ここで一番重要なんは、アルコール摂取量「**1.5g/kg**」という条件や。**70kg** の男性なら **105g**。これは純アルコール量で言うと、ビール中瓶（500ml）で 5〜6 本、焼酎なら 350ml、日本酒なら 5 合相当。
```

論理的にブロックを分けたい場合は空行で区切る:
```
ここで一番重要なんは、アルコール摂取量「**1.5g/kg**」という条件や。

**70kg** の男性なら **105g**。これは純アルコール量で言うと、ビール中瓶（500ml）で 5〜6 本、焼酎なら 350ml、日本酒なら 5 合相当。
```

### 2. 見出し階層は 2 段（H2 / H3 のみ）

note.com の見出しは「大見出し / 中見出し / 小見出し」の 3 階層。Notion → note.com で安定マッピングするため:

| Notion | note.com | 用途 |
|---|---|---|
| H1（タイトル） | タイトル | Notion ページの title プロパティに設定。本文ブロックには入れない |
| `## ` (heading_2) | 大見出し | 主要セクション（結論 / 本論 1〜N / まとめ / もっと深く知りたいなら / 脚注） |
| `### ` (heading_3) | 中見出し | 長い本論セクション内のサブ見出し（例: 「軽量帯 / 中量帯 / 重量帯」） |
| H4 以下 | 使わない | 階層を深くしない |

### 3. 自動 bold ルール（writer 側で `**...**` を付けて出力）

writer は以下を `**...**` で囲んで markdown を出力する。Phase 4 の `md_to_notion_blocks.py` が rich_text annotations の `bold: true` に変換する。

| 対象 | 例 |
|---|---|
| **数字 + 単位** | `**24%**` / `**1.5g/kg**` / `**70kg**` / `**20g**` / `**4 時間**` / `**5 倍**` / `**60g/日**` |
| **固有名詞（論文・著者・機関・専門用語）** | `**Parr et al. (2014)**` / `**PLoS ONE**` / `**Damas et al.**` / `**mTORC1**` / `**MPS**` / `**HRV**` / `**厚生労働省**` |
| **キー結論一文（各セクション末尾の言い切り）** | 例: `**設計してへん酒が悪い、ってことや。**` |

### 4. bold の過密化を防ぐ

同一段落内で bold が **3 箇所以上集中する場合は、最も強い 2 箇所だけに絞る**。視覚的に「文全体が太字に見える」のを避け、強調の効きを保つ。

### 5. 箇条書きと区切り線

- 箇条書き: `- ` で開始（writer 出力）→ `bulleted_list_item` ブロックに変換 → note.com の箇条書きとして反映
- 区切り線: `────────` または `---` → `divider` ブロック → note.com 上は水平線として表示（無視されるケースもあり、過信しない）

### 6. 引用ブロック（任意）

論文の直接引用や決め台詞を強調したい場合のみ `> 引用文` で markdown 出力 → `quote` ブロック。多用しない（1 記事 0〜2 箇所）。

## 投稿構成（6 ブロック）

### 1. 導入：手紙トーン（200〜350 字）

- 読者の課題を 2-3 行で言語化
- 「あなた」呼びは使わず、「俺ら」「俺たち」目線で語る
- 1 行目で読者を引き込む（フック型 or 問題提起型）
- 投入タイトルを冒頭の流れに自然に組み込む
- **関西弁の主張・呼びかけを織り交ぜる**（地の文は標準語ベース）

例:
```
スーパーで久しぶりにプロテインを手に取ったとき、値段を見て
ため息をついた人は多いはず。
3 ヶ月前と比べて、あきらかに数百円高い。

これ、来月もまた上がるで。
俺らの試算では、年内にもう 15% 上がる可能性が高い。
「気づいた頃には手遅れ」じゃ済まへん話やねん。
```

### 2. 結論先出し（150〜250 字）

- 記事全体の答えを最初に出す
- 3 行以内で言い切る
- 「なぜそうなるか」は次のブロックで詳細
- **結論は関西弁で言い切ると熱量が出る**

例:
```
結論はこうや。
ホエイは原乳価格に直結する。NZ・米国の原乳は今年 +18%。
カゼインは比較的安定。買い時は来月の値上げ前やで。
銘柄選ぶなら、NZ 製造で 1kg 4500 円以下がコスパ上限。
```

### 3. 本論：3〜5 セクション（1500〜2000 字）

各セクションは H2 見出し（`## 見出し`）+ 400〜700 字で構成する。

セクション構成パターン（カテゴリ別）:

| カテゴリ | セクション例 |
|---|---|
| compare（比較系） | 「A の特徴」「B の特徴」「結論：どちらを選ぶか」 |
| ingredient（成分解説） | 「作用機序」「推奨摂取量」「失敗する飲み方」 |
| debunk（誤認訂正） | 「世間の主張」「実際のデータ」「本当はどうすべきか」 |
| discovery（発見解剖） | 「異常な事例」「科学的分解」「実用への落とし込み」 |
| entertainment（エンタメ） | 「題材紹介」「科学的検証」「学びの着地」 |

各セクションの書き方:

- 数字を最低 1 つ入れる（割合、量、期間、論文数）
- 引用論文 1-2 件、PubMed ID を文中に自然に織り込む
- 段落は 2-4 行で改行
- 結論を最初に書き、根拠を後に続ける
- **論文引用・数値解説は標準語、解釈・主張・ツッコミは関西弁**で書き分ける

書き分け例:
```
（標準語：論文引用）
Parr et al. (2014) の実験で、トレーニング後にアルコール 1.5g/kg を摂取すると
筋原線維タンパク質合成が 24% 低下した。

（関西弁：主張）
プロテイン飲んでも相殺できへんかったってことや。
「飲んだら効果消える」って言われてもしゃあない数字やろ？
```

### 4. 具体例・体験談（200〜350 字）

- リアルな失敗例 or 成功例
- 一次情報（自分の体験、知人の事例、実測データ）
- 読者が自分ごと化できる場面を作る
- **体験談は関西弁が一番効く**（リアル感・人間味）

例:
```
俺らのチームでも、去年プロテインの買い方を変えた。
以前は「人気やから」で選んでたんやけど、原乳価格の四半期レポートを
見るようになってから、買い時を 1 ヶ月ずらすだけで月 2000 円浮いてん。
1 年で 24000 円。サプリ 1 本買えるレベルの差やで。
```

### 5. まとめ（150〜250 字）

- 結論を 3 行以内で再確認
- 行動につながる「次の一歩」を明示
- 押し付けがましくしない
- **まとめは関西弁で言い切ると締まる**

例:
```
プロテインは投資先やない、消耗品や。
情報が遅れた分だけ、財布が痩せていく。
来月の値上げ前に、自分の摂取量に合う銘柄を 1 つ決めとけ。
```

完成形例:

## 脚注・引用の作り方

記事末尾に「脚注」セクションを設け、5〜8 件の引用を載せる。

フォーマット:
```markdown
## 脚注

[1] PubMed ID: 12345678. Smith et al., 2023, "Whey protein synthesis rate". J Clin Nutr.
[2] NZ Ministry for Primary Industries Q3 2025 Report.
[3] 厚生労働省「日本人の食事摂取基準（2025年版）」.
[4] Manufacturer official spec sheet (XX社, 2024).
[5] AOAC International Method 2017.05.
```

- PubMed ID は数字で記載
- 公式情報源（メーカー、省庁、学会）は機関名 + 文書名
- リンクは Note の自動リンク機能を使うため URL 直書きでも可
- 一次情報を最低 3 件含める

## SEO 意識（見出し設計）

- H1（タイトル）: 投入されたタイトルそのまま
- H2（セクション）: 検索ワードを含める
- 例: 「## ホエイプロテインの値上げ予測 2026」

ただし SEO のために BB の口調を犠牲にしない。検索ワードを入れつつ、断定・体言止めを保つ。

## Threads との連動性

- タイトルは Threads と完全一致（投入タイトルそのまま）
- Threads で言及した結論を、Note では数字・論文・体験談で深掘り
- Threads の「結論先出し」と Note の「結論先出し」は同一論旨だが、字数と粒度が違う
- Threads から流入した読者が「ちゃんと裏付けがあった」と感じる粒度を確保
