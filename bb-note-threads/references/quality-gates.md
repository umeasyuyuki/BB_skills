# セルフチェック・品質ゲート

writer エージェントが Phase 2 出力前に必ず実行するセルフチェックと、Phase 3 の薬機法ゲート仕様。

## Phase 2 セルフチェック

threads-writer / note-writer は出力前に以下を全て確認する。1 つでも未達なら出力を保留し、修正してから提出する。

### A. 文字数・構造

- [ ] **A-1** 各ポストの字数が範囲内か
  - Threads 本体ポスト（親 + 本体リプ）: 200-300 字
  - Threads **最終リプ（D-2 二段構成）**: 240-300 字（メイン 100-150 字 + 区切り + サブ 100-150 字）
  - Note 全体: 2500-3500 字
- [ ] **A-2** 構造が揃っているか
  - Threads: 親 + 本体リプ + 最終リプ（型ごとのツリー深さ：⚪選系・ランキング系・データ型・問いかけ型(3構成版) = 3 / 体験談型・対比型・結論逆張り型・ストーリー型・問いかけ型(4構成版) = 4）
  - Note: 6 ブロック（導入 → 結論 → 本論 3-5 → 体験談 → まとめ → 関連リンク）
- [ ] **A-2-Threads** Threads 親ポストの 1 行目で対象者・状況が明示されているか
- [ ] **A-2-Threads-2** Threads 親ポスト末尾が「言い切らない引き」（「1 番のおすすめは、」「気をつけたのは、」「⭕️ 続く人は、」「この 3 つを見れば、」「ただし残り半分は、」「結論から言うと、」「調べてみると、」等）で切れているか
- [ ] **A-2-Threads-3** 本体リプの末尾は引きを作るか結論を言い切るか、型ルール通りか
- [ ] **A-2-Threads-4** 型選択メモが出力末尾にあるか（採用案 / 不採用案 / 採用理由が各 1-2 行）

### B. 外部導線の安全性（D-2 二段構成）

- [ ] **B-1** Threads 最終リプが **D-2 二段構成（Note 案内メイン + 区切り + LINE OC 匂わせサブ）** になっているか
- [ ] **B-1-2** 最終リプの間に区切り（`ーーー` または空行 2 行）が入っているか
- [ ] **B-1-3** 最終リプ サブ部分が「プロフィールの相談室」「ゆる〜く議論しています」「見るだけ参加も大歓迎」の温度感になっているか
- [ ] **B-2** Threads 全体に `line.me` の直 URL が含まれていないか
- [ ] **B-3** Threads 本体ポスト（親 + 本体リプ）に LINE 関連の言及が混入していないか（LINE OC 匂わせは最終リプのサブ部分のみ）
- [ ] **B-4** Threads 全体に強い誘導語（`完全無料` / `日本最先端` / `ステータス` / `読んでいるだけで` / `今すぐ参加` / `全員入って` / `LINE はこちら` / `プロフィールから↓` / `👇`）が含まれていないか
- [ ] **B-5** Note の場合、末尾見出しが `## 関連リンク` になっているか
- [ ] **B-6** Note の場合、公式 LINE オープンチャット名と実リンクが含まれているか
- [ ] **B-7** Note の場合、「個別の医療相談や診断をする場所ではありません。」が含まれているか
- [ ] **B-8** Note 末尾の LINE URL が指定の公式オープンチャット URL のみになっているか

### C. Note URL プレースホルダ（Threads のみ）

- [ ] **C-1** Threads **最終リプ（メイン部分）** に `【★Note URL を貼る★】` プレースホルダが含まれているか（本体ポストには絶対入れない / Note 出力時はこの項目を「N/A」とする）
- [ ] **C-2** 本体ポスト（親 + 本体リプ）に URL が混入していないか（URL は最終リプ メイン部分専用）

### D. 文体・口調（低温の標準語 BB トーン）

- [ ] **D-1** Threads 本文が低温の標準語 BB トーン（断定・体言止め・数字で強く言う）になっているか
- [ ] **D-2** AI っぽい曖昧表現が混入していないか
  - 禁止: 「ケースバイケース」「一概には」「個人差があります」「人による」「最適化」「アプローチ」「プロトコル」「フレームワーク」「ソリューション」
- [ ] **D-3** 同じ語尾の 3 回連続が無いか
- [ ] **D-4** Markdown 記号（`**`、`##`）が本文中に残っていないか（Note の見出し H2 と自動 bold は OK、Threads は NG）
- [ ] **D-5** Threads 本文で `俺ら` / `俺たち` を原則使っていないか（使う場合もツリー全体で 1 回まで）
- [ ] **D-6** 「ぶっちゃけ」「知らないと損」「全員これ」「〜っしょ」「〜じゃん」「〜だよね」など、関西弁ではないが温度が高い口語が混入していないか

### G. 専門用語の翻訳（★必須）

学術略称・カタカナ専門語・専門単位は読者の語彙へ翻訳する（[domain-vocabulary.md](./domain-vocabulary.md) を必ず参照）。

- [ ] **G-1** 学術略称が本文で素のまま使われていないか
  - 禁止（本文素使用 NG）: `ACSM` / `Position Stand` / `PubMed` / `mEq/L` / `mOsm/L` / `Osmolality`
  - OK: 初出のみ「世界のスポーツ医学団体（ACSM）」のように補足、以降は日常語（「世界のガイドライン」「液体の濃さ」等）
- [ ] **G-2** カタカナ専門語が翻訳されているか
  - 翻訳必須: `アイソトニック` → `体液と同じ濃さ` / `ハイポトニック` → `体液より薄い` / `グリコーゲン` → `筋肉のエネルギータンク` / `mTORC1` → `筋肉が作られるスイッチ` / `MPS` → `筋肉の合成` / `インスリン応答` → `血糖が上がったときの体の反応` / `生体利用率` → `体に届く割合`
- [ ] **G-3** BCAA / EAA / WPI / WPC は初出に日常語訳が併記されているか
  - 例: 「BCAA（必須アミノ酸の一種）」「WPI（精製度の高いホエイ）」
- [ ] **G-4** 専門単位（mEq/L、mOsm/L 等）が本文で mg/L、g/L、「液体の濃さ」等に変換されているか（原単位は脚注のみ）
- [ ] **G-5** 論文著者名（Parr et al. 等）・PubMed ID が Threads 本文に出ていないか（Note 脚注のみ OK）
- [ ] **G-6** 数値・単位（%、mg、g、kcal、円、年、時間）は無翻訳で残っているか（翻訳しすぎていないか）

### E. 関西弁全面禁止（★必須）

旧仕様の関西弁レベル 2 / ハイブリッド関西弁は廃止。**全文を通じて関西弁が一切混入していない**ことを確認する。

- [ ] **E-1** 関西弁の語尾が混入していないか
  - 禁止: 「〜やで」「〜ねん」「〜やん」「〜やろ」「〜まんねん」「〜でんねん」「〜やんけ」「〜あかん」
- [ ] **E-2** 関西弁の接続詞が混入していないか
  - 禁止: 「ほな」「せやから」「せやけど」
- [ ] **E-3** 関西弁の副詞・表現が混入していないか
  - 禁止: 「めっちゃ」「ほんま」「えらい」「ちゃう」「ええ感じ」「知らんけど」「ええんちゃう？」
- [ ] **E-4** 論文引用・数値解説部分が「である」調で淡々と記述されているか
- [ ] **E-5** Threads 本文で「俺ら」「俺たち」を連発していないか。Note 本文で使う場合も、関連リンク案内では押し出しすぎていないか
- [ ] **E-6** 関連リンク案内に「あなた」「皆様」「読者の方」「視聴者の皆さん」が混入していないか
- [ ] **E-7** Threads 最終リプと Note 末尾が、温かく、ゆるく、押し付けがましくないか

### F. note.com コピペ最適化（★必須、Note のみ）

- [ ] **F-1** Note 本文の各 paragraph は **1 行で完結**しており、ブロック内に `\n` を含まないか
- [ ] **F-2** 見出しは `## ` (H2) と `### ` (H3) のみ、H4 以下が使われていないか
- [ ] **F-2-TOC** 導入直後に `[TOC]` が単独行で入り、前後に空行があるか
- [ ] **F-3** 数字 + 単位（例: `24%`、`1.5g/kg`、`70kg`、`4 時間`、`5 倍`）に `**...**` が付いているか（最低 5 箇所以上）
- [ ] **F-4** 固有名詞（論文名・著者・機関・専門用語、例: `Parr et al. (2014)`、`PLoS ONE`、`mTORC1`、`MPS`、`厚生労働省`）に `**...**` が付いているか
- [ ] **F-5** 各セクション末尾の **キー結論一文**に `**...**` が付いているか
- [ ] **F-6** 同一段落内で `**...**` が **3 箇所以上集中していない**（最大 2 箇所まで、過密化を防ぐ）
- [ ] **F-7** 区切り線は `────────` または `---`、引用は `> `、目次は `[TOC]`、それ以外の Markdown 拡張記法（テーブル、コードフェンス等）は本文に含まれていないか
- [ ] **F-8** note.com 保存用本文から管理メタ情報（`title_input:`、`文字数:`、`セルフチェック結果` 等）を削除できる構造になっているか

注意: F-1〜F-7 は **Note のみ**の項目。Threads は本文の rich_text 構造が単純な平段落なので対象外。

## Phase 3 薬機法ゲート

`tiktok-fit-compliance-check` を呼び出し、Threads と Note の両本文を並列でチェックする。

### 判定基準

| 判定 | 基準 |
|---|---|
| **Green** | 違反なし、Phase 4 へ進行 |
| **Yellow** | グレーゾーン表現あり、ユーザーに最終判断を委ねる |
| **Red** | 明確な薬機法違反あり、writer に修正依頼 |

### Red 判定時のリトライ手順

```
リトライ 1 回目:
  → writer に違反箇所と修正提案を渡し、修正版を生成依頼
  → 再度 compliance-check を実行

リトライ 2 回目:
  → 同上
  → 再度 compliance-check を実行

3 回目以降:
  → ユーザーに手動修正を依頼（中断）
```

### 修正依頼テンプレ

```
以下の表現が薬機法上 Red 判定でした:

違反箇所: "{違反テキスト}"
違反タイプ: {効能効果の暗示 / 治療効果の標榜 / 等}
重大度: {高 / 中 / 低}
修正提案: "{言い換え案}"

該当箇所を修正し、表現を弱めるか、エビデンス引用形式に変更してください。
全体の論旨は維持すること。修正版を出力してください。
```

### Yellow 判定時の挙動

```
ユーザーに以下を提示:
  - 違反箇所
  - グレーゾーンの理由
  - そのまま投稿するリスク（重大度: 低 / 中 / 高）
  - 修正案（あれば）

ユーザーの判断:
  - "そのまま" → Phase 4 へ
  - "修正" → writer に修正依頼（Red と同じフロー）
```

## サプリ・栄養テーマでの追加チェック

ingredient カテゴリの場合、以下を追加でチェックする:

- [ ] 効能効果の暗示（「○○が効く」「○○を治す」等）が無いか
- [ ] 「医薬品的」表現が無いか
- [ ] 安全性に関する誤解を生む表現が無いか
- [ ] 推奨摂取量を超える量を勧めていないか
- [ ] 薬剤師チームの監修済みであることが文中に示されているか（強制ではない、推奨）

## 失敗時のエラーログ

セルフチェック未達 / 薬機法 Red 連続 3 回時、以下のログを `output/<timestamp>/error.log` に保存する:

```
timestamp: 2026-04-28T13:45:00Z
phase: 2 (writer) / 3 (compliance)
agent: threads-writer / note-writer
fail_type: selfcheck_incomplete / compliance_red_3times
fail_items: ["B-2", "E-1"]
retry_count: 3
last_output_excerpt: "..."
```

ユーザーが原因を分析し、後続の改善に使えるようにする。
